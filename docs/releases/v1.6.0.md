# v1.6.0 — Shipped systemd helper and a locations poll that stops hammering a crashing CLI

> **Language / Idioma:** English first, Português (Brasil) below.

Release date: 2026-08-02

## Highlights

- **The optional systemd lifecycle helper is now shipped** as `scripts/adguardvpn-dms-control` instead of being described in prose, so `useSystemdService` users no longer have to write it themselves. Its `connect-fastest` and `connect-location` are idempotent: they exit `0` without touching `systemctl` when the unit is already active on the requested target. An unconditional `systemctl restart` drops the tunnel for a few seconds — NetworkManager flags the interface as unmanaged and systemd-resolved swaps DNS servers — so a click that changed nothing was causing a real network outage. `--force` restores the unconditional restart.
- **The background locations poll no longer amplifies an upstream CLI bug.** `adguardvpn-cli list-locations` segfaults intermittently; at the old cadence (`refreshIntervalSec × 6`, min 30 s) that produced a coredump every few minutes and no data. The poll is now `refreshIntervalSec × 60` (min 15 min) and doubles on each failed refresh up to 1 h, resetting on the first success. The list is near-static, so nothing is lost.
- **A failed refresh no longer blanks the location picker.** `locations` is only replaced by a successful parse, so the last known-good list survives both a crashed CLI and unparseable output.
- **A crashed refresh is now visible.** A segfault prints nothing, so `lastError` stayed empty and the failure was silent. The new key `status.locations_command_failed` reports the exit code.

## Compatibility

- Requires DankMaterialShell `>= 1.4.0`.
- Requires `adguardvpn-cli` in `PATH` or a configured binary path.
- No settings migration is required. `refreshIntervalSec` keeps its meaning; only the multiplier applied to the locations timer changed.
- The manual refresh in the popout is unchanged and still refreshes locations immediately.
- One new translation key (`status.locations_command_failed`), present in all 22 locales.

## Validation

- All 31 parser tests pass.
- i18n key validation passes with strict parity for all 22 locales.
- Markdown and QML syntax validation pass.

## Português (Brasil)

Data de lançamento: 2026-08-02

### Destaques

- **O helper opcional de ciclo de vida via systemd passa a ser distribuído** em `scripts/adguardvpn-dms-control`, em vez de apenas descrito em prosa, então quem usa `useSystemdService` não precisa mais escrevê-lo por conta própria. Seus comandos `connect-fastest` e `connect-location` são idempotentes: saem com `0` sem tocar no `systemctl` quando a unit já está ativa no destino pedido. Um `systemctl restart` incondicional derruba o túnel por alguns segundos — o NetworkManager marca a interface como `unmanaged` e o systemd-resolved troca de servidor DNS — ou seja, um clique que não mudava nada estava causando uma queda de rede real. `--force` restaura o restart incondicional.
- **O poll automático de localizações deixa de amplificar um bug do CLI.** O `adguardvpn-cli list-locations` sofre segfault intermitente; na cadência antiga (`refreshIntervalSec × 6`, mín. 30 s) isso gerava um coredump a cada poucos minutos e nenhum dado. O poll passa a ser `refreshIntervalSec × 60` (mín. 15 min) e dobra a cada refresh falho até 1 h, voltando ao normal no primeiro sucesso. A lista é quase estática, então nada se perde.
- **Um refresh falho não zera mais o seletor de localizações.** A propriedade `locations` só é substituída por um parse bem-sucedido, então a última lista válida sobrevive tanto ao CLI quebrado quanto a uma saída ilegível.
- **Um refresh que quebra agora fica visível.** Um segfault não imprime nada, então o `lastError` continuava vazio e a falha era silenciosa. A chave nova `status.locations_command_failed` mostra o código de saída.

### Compatibilidade

- Requer DankMaterialShell `>= 1.4.0`.
- Requer `adguardvpn-cli` no `PATH` ou um caminho de binário configurado.
- Nenhuma migração de configurações é necessária. O `refreshIntervalSec` mantém o significado; mudou apenas o multiplicador aplicado ao timer de localizações.
- O refresh manual do popout permanece igual e continua atualizando as localizações na hora.
- Uma chave de tradução nova (`status.locations_command_failed`), presente nos 22 locales.

### Validação

- Todos os 31 testes de parser passam.
- A validação i18n passa com paridade estrita para os 22 locales.
- As validações de Markdown e sintaxe QML passam.
